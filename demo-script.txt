SÉANCE DEMO SCRIPT  (Software story)
About three minutes. Three screens: the owner console (Sam, Software), Priya's chat
(Controls) and Alex's chat (Robotics). Everyone is inside Acme Robotics. Type exactly
what is written here. Don't improvise.

Screens
  Owner console      http://127.0.0.1:3000   (Sam, owner of the Software agent)
  Priya, Controls    http://127.0.0.1:3001
  Alex, Robotics     http://127.0.0.1:3002

Before every run
  1. scripts/demo.sh stop && scripts/demo.sh        (from the repo root)
  2. bun scripts/warmup.ts
  3. Press Reset on the console. Both chats empty, counters 0, both team boxes unticked.
  4. bun scripts/preflight.ts                        every line must say ok

DON'T
  - Don't refresh a chat page. Its answers are only on the page.
  - Don't ask @software anything before Sam clicks Teach agent (it would page Sam).
  - Don't restart anything during the demo.


BEAT 1 · Sam teaches his agent once            ("Ask the agent, not the engineer.")
Page: console, "Teach your agent" panel. The fields are pre-filled:
  What is it?   X database ingest format
  The details   Send JSON to the X database /ingest endpoint. Each record:
                device_id (string), ts (ISO-8601, UTC), metric (string),
                value (number), unit (SI unit string). Batch up to 500 records
                per POST; gzip bodies over 1 MB.
Click Teach agent.
Should appear: "Saved as sof-T1. Tick the teams that may ask." Learned reads 1.
Then, under "Which teams can ask the Software agent?", tick Controls only.
Say: Sam writes it once and decides which teams may ask. It lives in his
team's Durable Actor, not in a shared bot.


BEAT 2 · Controls gets the answer without bothering Sam
Page: Priya. Type, then press Enter:

  @software What format should data be in to send it to the X database?

Should appear on Priya's page (about 1-2 s):
  Software with a green "answered" pill: JSON, the five fields (device_id, ts,
  metric, value, unit), 500 records per POST, gzip over 1 MB, and
  Sources: sof-T1 X database ingest format. (Wording varies a little per run.)
Should appear on the console:
  Interruptions avoided 1. Repeats served 1. A row in the timeline and audit log
  (asker-priya, Answered, used sof-T1). The flow strip lights asker-priya ->
  Agent Relay -> expert-software and back.
Say: Priya's agent asked Sam's agent over Agent Relay. Sam wasn't interrupted.


BEAT 3 · Robotics isn't allowed yet
Page: Alex. Type, then press Enter:

  @software What format should data be in to send it to the X database?

Should appear on Alex's page:
  Software with a red "refused" pill: "I can't share that at your access level."
  1 withheld: "Sam documented this for approved teams only." and
  "You can ask Sam for access."
Should appear on the console:
  Requests refused 1. Audit log: asker-robotics, Refused, withheld sof-T1.
Say: Relay proves who is asking; the actor checks the team before the model sees
anything. Robotics never got the text, not even into the prompt.


BEAT 4 · Sam opens it to Robotics, live
Page: console. Tick Robotics. (No Save button: it applies at once.)
Page: Alex. Type the same question again, then press Enter:

  @software What format should data be in to send it to the X database?

Should appear on Alex's page:
  Software with a green "answered" pill, the same format, Sources: sof-T1.
Should appear on the console:
  Interruptions avoided 2. Repeats served 2.
Proves: the owner controls who can ask, per team, and it takes effect instantly.


CLOSE · the audit log
Page: console, scroll to the Audit log. Four rows: Sam learned sof-T1,
asker-priya answered, asker-robotics refused (withheld sof-T1), asker-robotics
answered. Guard catches 0.
Say: data stays home, answers travel. Every answer and refusal is on record.

After the run: press Reset (removes sof-T1, unticks both boxes, clears both chats).
